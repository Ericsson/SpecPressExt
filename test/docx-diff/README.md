# DOCX DIFF Tests

This directory contains test fixtures and end-to-end tests for the multi-version DOCX DIFF functionality.

## Quick Start

Run the complete end-to-end test:

```bash
cd test/docx-diff
node docx-diff-e2e.test.js
```

Or run as part of the full test suite:

```bash
npm test
```

This single command:

1. Generates DOCX files from markdown sources in `%TEMP%`
2. Runs VBScript to merge them with tracked changes
3. Validates the output contains expected changes
4. Cleans up temporary files

## Testing with VBScript

To manually test the multi-version merge with these fixtures:

```cmd
cd c:\Data\git\repo\GitHub\SpecPressExt\test\docx-diff

cscript ..\..\scripts\merge-multi-version.vbs output.docx test-v1.docx test-v2.docx "Author_v2" test-v3.docx "Author_v3" test-v4.docx "Author_v4"
```

This generates `output.docx` with tracked changes showing:

- Changes from v1 to v2 attributed to "Author_v2"
- Changes from v2 to v3 attributed to "Author_v3"
- Changes from v3 to v4 attributed to "Author_v4"

Expected result:

- Additions appear in blue underline
- Deletions appear in red strikethrough
- Each change shows the correct author name
- All 4 versions are properly merged

## Verification

### Automated Verification

To automatically verify the tracked changes in the output DOCX:

```bash
cd test/docx-diff
node verify-docx-diff.js [output.docx]
```

This script:

1. Extracts `word/document.xml` from the DOCX file
2. Parses all tracked changes (insertions and deletions)
3. Groups changes by author name
4. Validates against expected changes
5. Reports pass/fail status

**Expected Results:**

- Author_v2: ~30 insertions (additions from v1 to v2)
- Author_v3: ~32 insertions, ~7 deletions (including Channel Capacity deletion)
- Author_v4: ~86 insertions (including new QoS section)
- Overall: PASSED

### Manual Verification

Open `output.docx` in Microsoft Word and:

1. **Check Review tab** → Tracking → Show Markup → All Markup
2. **Filter by author**:
   - Select "Author_v2" to see v1→v2 changes
   - Select "Author_v3" to see v2→v3 changes
   - Select "Author_v4" to see v3→v4 changes
3. **Verify specific changes**:
   - Section 5.2 should be deleted (red strikethrough) by Author_v3
   - Section 9 should be added (blue underline) by Author_v4
   - Tables should show proper cell-level tracking

## Use in Automated Tests

These fixtures can be used in automated tests:

```javascript
const fixture1 = path.join(__dirname, 'test', 'docx-diff', 'test-v1.docx')
const fixture2 = path.join(__dirname, 'test', 'docx-diff', 'test-v2.docx')
const fixture3 = path.join(__dirname, 'test', 'docx-diff', 'test-v3.docx')
const fixture4 = path.join(__dirname, 'test', 'docx-diff', 'test-v4.docx')

// Test 2-version merge
testMerge([fixture1, fixture2], ['Author_v2'])

// Test 4-version merge
testMerge([fixture1, fixture2, fixture3, fixture4], ['Author_v2', 'Author_v3', 'Author_v4'])
```

## Maintenance

When updating the test fixtures:

1. Modify the markdown files (`test-v1.md` through `test-v4.md`)
2. Run `node generate-docx.js` to regenerate DOCX files
3. Commit both markdown and DOCX files to git
4. Update this README if the change patterns are modified
